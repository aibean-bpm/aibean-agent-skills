# 临时 AiBean API 认证

## 适用范围

流程元数据查询、流程表/默认表单绑定、菜单读取/保存以及其他在线 AiBean API 都要求认证。Server API 的 `/api` 与 Biz API 代理的 `/bapi` 共用同一个令牌。这个要求只影响智能体在开发过程中调用运行中的 API；最终 Vue 页面仍通过项目既有请求封装和用户自己的登录态访问 API。

## 获取与保存

1. 先检查当前智能体会话是否已经具有可用的 AiBean API 认证上下文。
2. 没有时，根据环境提供安全登录：通过本地密码输入框或终端隐藏输入账号和密码，由本地进程登录。不要要求用户把密码或令牌发到聊天中；若无法安全输入，停止在线操作，允许用户选择安全提供临时 Token。
3. 使用用户确认的本地开发或测试服务地址，通过现有 `/api` 代理调用 `POST /api/auth/apilogin`，JSON 请求体为 `{"username":"<账号>","password":"<密码>"}`。该接口明文接收密码，仅用于开发联调；使用可信连接，避免向不明地址发送凭据。
4. 从登录响应的 `data.accessToken` 取得令牌，构造 `Authorization: Bearer <accessToken>`；`/api` 和 `/bapi` 共用此令牌。也允许用户通过安全输入直接提供已有的 `Authorization: Bearer <token>`。
5. 密码仅在本地登录进程内短暂使用，登录后立即丢弃；不要将密码、accessToken 或 refreshToken 写入聊天、命令行参数、shell 历史、源码、配置、Git、文件、URL、日志、异常或测试夹具。不要打印完整登录响应；无需使用 refreshToken 时丢弃它。
6. 令牌仅保存在当前会话的内存或临时进程作用域。需要环境变量时使用 `AIBEAN_API_AUTHORIZATION`，禁止打印或持久化。用户自行输入密码时，确保输入不回显且不会出现在工具调用参数或输出中。

## 失败处理

- 登录失败时提示用户检查账号或环境，不自动重复尝试。遇到 401 或 403，立即停止所有在线 AiBean API 调用，提示用户重新登录或提供新的临时令牌。
- 不反复重试、探测其他认证方式、使用硬编码默认账号，或在 `/api` 与 `/bapi` 之间切换以规避认证失败。
- 用户不登录也不提供令牌时，继续完成不依赖在线 API 的本地源码分析与代码编写；将需要在线查询或写入的步骤列为未执行项。
